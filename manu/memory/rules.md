## 〇、【最高优先级铁律·零】本地优先！永远先改本地工程代码，再同步到服务器！

> 本条优先级高于本文档其余全部铁律。违反即为严重操作事故。

- **铁律正文**：任何代码、脚本、配置、文档（含 `manu/memory/` 内全部 memory 文件）的修改，
  **一律且只能先在本地工程 checkout 中完成**，然后再由 Agent 同步到服务器工程目录。
  **严禁把服务器目录当作编辑目标直接改写。**

- **本地 vs 服务器路径对照**（操作地基）：

  | 角色 | 路径 | 允许的操作 |
  | :--- | :--- | :--- |
  | **本地工程 checkout（唯一可写编辑区）** | `/media/manu/1TB-Volume/workspace/qlib/`（内含完整 `manu/`） | ✅ **所有 Edit/Write 都发生在这里** |
  | 服务器工程目录 | `/tmp/pycharm_project_658d3fc4` | ⛔ **只读 + 同步落地区，禁止 Edit/Write** |
  | 本机 SSHFS 镜像 | `/home/manu/mnt/pycharm_project_658d3fc4` | ⛔ **只读 ro**，写不进去，**不是推送通道**，只能读 |

- **标准工作流（强制三步，不可跳步）**：
  1. **本地编辑**：在 `/media/manu/1TB-Volume/workspace/qlib/` 下用 Edit/Write 完成全部修改；
  2. **本地校验**：本地跑通 `grep`/`diff`/语法检查，确认改动确实落在这里；
  3. **同步落地**：`bash manu/tools/sync_to_server.sh`（rsync over ssh + **md5 双侧比对**）。

- **🔴 本工程的三个实测坑（必须记住）**：
  1. **本机 `ssh` 直接跑会报 `Bad owner or permissions on /etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf`**
     ⇒ 所有 ssh/scp/rsync **必须加 `-F /dev/null`** 绕过系统 ssh_config。同步脚本已内置。
  2. **服务器 sshd 在 32222 端口，22 端口是关闭的**（用 22 会 `Connection refused`）。
  3. **本机 SSHFS 镜像只读** ⇒ 推送只能用 rsync/scp 直接打服务器，**不能**「写挂载点」。

- **🔴 PyCharm 协同边界（本工程特有，最易踩）**：
  - **同步方向**只允许「本地 → 服务器」；
  - 但 PyCharm 的 `autoUpload=Always`（`.idea/deployment.xml`）会产生**反向写入**：
    **用户在 PyCharm GUI 里改的文件会被自动推上服务器，而本地 checkout 不变**；
  - ⇒ **发现本地与服务器分叉时，必须先问用户「这批差异是不是我在 PyCharm 里改的」**，
    再决定以哪侧为准；**严禁**在未确认前用本地覆盖服务器（会静默抹掉用户的 GUI 改动）；
  - ⇒ **只读 `rules.md` 的 Agent 会误以为「`autoUpload=Always` ⇒ 服务器永远最新」而跳过同步脚本**
    —— **同步脚本必须跑**：它覆盖「**Agent 在命令行改的文件**」（PyCharm 不感知这部分）。

- **发现本地与服务器分叉时的修复流程**：**默认以本地为准重做，不要反向覆盖本地**。
  先 `diff` 确认分叉范围，把改动在本地重做，再由本地覆盖服务器。
  **严禁用 `cp <服务器> <本地>` 把服务器版本倒灌回本地**（会把本地未同步的改动全部丢掉）。
  **例外**：若差异经用户确认来自 PyCharm GUI 改动 ⇒ 应当**以服务器为准把改动落回本地**，
  但**仍必须先向用户确认**再执行。

- **与「禁擅自启动重活」（铁律一）的关系**：铁律一是**禁止 Agent 跑重型训练/回测**，
  本条是**禁止 Agent 越界写入服务器**。两者方向相反、互不豁免：
  既不能因为「要同步」就去服务器上动手改，也不能因为「不许跑」就把文件留在本地不同步。

## 一、【铁律一】严禁 Agent 擅自启动任何重型任务

- **重活定义**：全量数据下载、模型训练、全量回测（backtest）、特征重建、长时间数据预处理、
  **任何 >5 min 的任务**。
- 这些**必须用户当轮明确授权**才能启动。
- **轻活允许**（无需逐次授权）：读代码、读 memory、编辑代码与文档、`git status/diff/log`、
  小样本冒烟（≤1 min）、**只读**环境探查（`pip list` / `python -c "import qlib"`）。
- **🔴 环境探查的已知陷阱（本工程实测）**：
  - 服务器工程目录**无 `.git`** ⇒ 任何安装/重装**必须**带 `SETUPTOOLS_SCM_PRETEND_VERSION=0.9.8`，
    否则 setuptools_scm 探测不到版本而失败（`pip install -e .` 会炸）；
  - 服务器**未装 `torch`/`xgboost`**（qlib 视为 optional，缺失只打 info 日志并静默跳过）
    ⇒ 用 `TorchModel`/`XGBModel` 前须**另行授权安装**；
  - 🔴 **`rl` extra 会把 numpy 降到 1.x**（`numpy<2.0.0` 钉在 `rl` extra 里），
    而当前 numpy 是 **2.5.4** ⇒ **不要顺手 `pip install -e ".[rl]"`**，
    会把整个环境的 numpy 降级、影响所有已装好的包；
  - ⚠️ numpy 2.x 下有两处**上游 latent bug**：`qlib/contrib/report/data/ana.py:102` 用 `np.int`
    （已移除别名）；`qlib/rl/data/pickle_styled.py:268` 用 `DataFrame.append`（pandas 2.x 已移除）。
    ⇒ 这两条路径报错时**先怀疑 numpy/pandas 版本**，不要直接改上游源码（铁律六）。
- **量化场景的最小冒烟**：允许「**≤N 天 × ≤M 只股票**」的小样本回测（≤1 min、无 GPU）。
  超出此规模 ⇒ 属重活，需授权。
- **qlib 的重活入口**：`scripts/get_data.py`、`scripts/dump_bin.py`、`examples/benchmarks/`、
  `qlib/contrib/rolling/`、全量 `qrun` 工作流。

## 二、【铁律二】缓存与数据体积必须克制

- qlib 的 `.pkl` / `.bin` / features cache 极易膨胀到数十 GB。
- **纪律**：
  - 缓存文件必须落在 **`/mnt/data/...`**（服务器持久盘 7.4 T），**禁止**写进 `/tmp`（根分区仅 3.4 T，
    写满会丢）；
  - 生成 cache 前先估算体积；**单文件 >10 GB 必须先与用户确认**；
  - 定期清理中间产物，**保留最终产物与关键中间量**；
  - 铁律：pkl 等 cache 控制在 **~100 MB 级**，严禁数十 GB 冗余缓存。

## 三、【铁律三】本地改动必须同步到服务器，并做 md5 双侧比对

- **义务**：本地任何代码、脚本、配置、文档修改完成后，**必须立即**同步到服务器工程目录。
- **杜绝用户二次操作**：用户无需手动复制或同步代码。
- **同步范围**：`manu/tools/sync_to_server.sh` **默认只推 `manu/`**。
  若改了 `manu/` 之外的东西（`examples/`、`pyproject.toml`、`qlib/` 下任何文件），
  **必须显式传路径**：`bash manu/tools/sync_to_server.sh examples pyproject.toml`。
- **判据**：**只能用 md5 双侧比对**（本地 vs 服务器），**禁止**用「命令返回 0」当作同步成功。
- **🔴 md5 比对的口径前置条件**：两侧必须**同排除项 + 同排序口径**（`LC_ALL=C sort -z`）
  + 远端 md5 输出需**滤掉 SSH 噪声行**（`WARNING|store now|openssh.com|hostfile_replace|update_known`）。
  否则会得到「两边 md5 值完全相同、却报不一致」的**假阳性** ⇒ 进而误以为同步失败而乱改，
  **这比不比对更糟**（本工程已实测踩过，见 `manu/memory/env_setup_20261104.md` §5.3）。
  脚本已内置这三条；**自己手搓 `md5sum` 比对时必须照做**。
- **工具**：`bash manu/tools/sync_to_server.sh`（自带 md5 双侧比对与 diff 定位）。
- **「已同步」≠「本地已改」**——2026-10-10 在 yolo 工程真实发生过「直接改 SSHFS 镜像、
  本地 checkout 一行未变」的静默分叉事故。

## 五、【铁律五】重大非继承性实验严禁越级对比，必须同源受控 A/B

- **方法论红线**：涉及数据预处理口径变更、特征体系变更、模型结构变更等
  **无法无损继承当前基准**的改动，**严禁**直接拿未充分训练的新模型与基准做断崖式对比，
  防止把「训练不充分/超参未适配」误判为「方案失效」而误杀潜力方案。
- **双胞胎受控对照规范 (Twin A/B Test)**：
  - 对照组 A（现有基准）与实验组 B（新方案）必须**同数据、同特征、同回测区间、同手续费/滑点假设、
    同初始资金、同随机种子**；
  - 唯一变量是那一个被改动的因素；
  - 唯有当 B 在**全部关键指标上不劣于 A**（或在明确标注的口径下更优）⇒ 才允许立项深训/深调；
  - **任何「优于已发表的基准 / 官方口径」的结论，必须先自证「同源可比」**
    （同 universe、同区间、同 freq、同成本、同种子）。

## 六、【铁律六】上游源码冻结：一切自研改动走 `manu/` 扩展层

- **背景**：qlib 是**上游开源项目**（`microsoft/qlib`），直接改 `qlib/` 包源码会：
  (a) 无法与上游同步；(b) 上游安全修复/功能更新无法 merge；(c) 复现别人环境时口径不明。
- **纪律**：
  - **禁止**直接修改 `qlib/`、`examples/`、`tests/` 下的上游文件；
  - 自研代码一律放 **`manu/`** 下的扩展层（`manu/experiments/`、`manu/data/`、`manu/evaluation/` 等）；
  - 需要改上游行为时，用 **subclass / wrapper / 注入配置**的方式在 `manu/` 里做，**不碰原文件**；
  - 若确需 patch 上游 ⇒ 必须写成 **独立 `.patch` 文件**放 `manu/tools/patches/`，
    并在 memory 记录「patch 了什么 / 为什么 / 如何重放」，**禁止**直接改树。
- **例外**：用户明确要求「改上游某文件」时，以用户指令为准，但**必须在 memory 里留痕**。

- **🔴 委派 prompt 必须自包含**（移植自 yolo §八），至少含五要素：

## 十、【铁律十】算力归属：重活一律上服务器 ＋ host 资源自监控

- **背景**：用户 host 与日常办公同机，**CPU/内存有限**。
- **铁律正文**：
  1. **重活一律上服务器** `192.168.99.40`（`ssh -F /dev/null -p 32222 huangzhe@192.168.99.40`）。
     host 只做：代码编辑、产物读写、md5 与口径抽检、文档编辑、产物同步。
  2. **host 上不得并行起 >1 个重活**；单重活 `OMP_NUM_THREADS ≤ 3`、`MKL_NUM_THREADS ≤ 3`。
  3. **禁止 `nohup &` 挂常驻重活**——沙箱会回收，主机重启会连带杀死。
  4. **禁止与既有任务抢资源**（GPU/核/磁盘 IO）。
  5. **必须自监控 host 资源**：每次起活**前**查 `uptime` / `free -g`；
     **load > 6 或 available 内存 < 3 GB ⇒ 不得起新重活**。
     **已有重活时若越线 ⇒ 主动降线程或迁移到服务器，并在报告里说明**（补 yolo §十三·5 末的补救动作与报告义务）。
  6. **服务器重活必须用 `setsid nohup` 脱离 SSH 会话**（否则 SSH 断开即死），
     且日志落在 `/mnt/data/`。
- **服务器工程目录是 `/tmp/pycharm_project_658d3fc4`（ext4 `/dev/nvme0n1p2`，非 tmpfs）**
  ⇒ 重启不清空；但它落在**根分区**，写满会**撑爆根分区**、导致系统与工程目录不可用
  ⇒ **关键产物必须另存 `/mnt/data`**（`/dev/sda`，7.4 T）。
- **服务器是共享机器（80 核，多项目共用）** ⇒ **测量耗时前必须先清残留进程**
  （移植自 yolo「板卡测量前置」：上一次残留的作业会直接污染耗时测量）。
- **起活升级路径**：本工程沙箱内 ssh **可用**（已实测），故 Agent 可自行推送并拉起作业。
  **若某次起活失败（ssh 不可达/权限问题）⇒ 不得反复重试刷屏**，
  应**升级给用户**：给出一条**完整可复制**的命令（含端口、conda 激活、cd、工作目录），
  让用户在沙箱外执行。

  - 墙钟截止必须带**硬截止 + 看门狗豁免**；
  - 子步骤 **rc 独立可查**；
  - 封存**幂等**（重复执行不产生副作用）；
  - **先出一版完整交付件当保险层**，再优化；
  - **门禁/评测的开始时刻必须晚于最后一条训练臂的完成时刻**；
  - 比率与相邻斜率**同批样本**，排序须**显式给 population**。

## 十二、【量化研究专属纪律】（新增，来自 qlib 场景）

> 本节全部条款的 qlib 技术断言均**经源码核验**（2026-11-04，qlib v0.9.8）。
> 核验依据写在各条括号内（`文件:行号`）。**改动本节前必须先读源码，不要凭记忆改。**

### 12.1 回测口径必须完整声明，禁止"只报收益"

任何一个回测数字被引用时，**必须同时给出**：

| 维度 | 必须声明 |
|:--|:--|
| 数据区间 | 起止日期 + **是否含样本外区间** + 是否含涨跌停/停牌 |
| 标的池 | 全市场 or 过滤后？过滤规则是什么？幸存者偏差处理？ |
| 成本假设 | 手续费（双边/单边）、印花税、滑点（固定 bp or 比例）、冲击成本 |
| 组合约束 | 调仓频率、持仓数上限、权重上限、换手率上限、是否允许做空/杠杆 |
| 基准 | 对比基准是什么？同区间同成本算出来的吗？ |
| 资金 | 初始资金、复利方式 |

- **成本假设在 qlib 有确切落点**（`qlib/backtest/exchange.py:44-51`），必须逐项点名，不得凭记忆填：

  | 参数 | qlib 默认 | 含义 |
  |:--|:--|:--|
  | `open_cost` | `0.0015` | 买入费率 |
  | `close_cost` | `0.0025` | 卖出费率 |
  | `min_cost` | `5.0` | 最小佣金 |
  | `impact_cost` | `0.0` | 冲击成本 |
  | `deal_price` | — | 成交价口径（`close` / `open` / `vwap` / 阈值价） |
  | `limit_threshold` | `0.095` | 涨跌停阈值（**相对 `region` 变化**，`qlib/config.py:316-320`） |
  | `trade_unit` | `100` | 交易单位（**A 股一手 = 100 股**） |

  ⇒ **「成本假设」一栏必须写清这 7 个参数的实际取值**，而不只是写「含手续费」。

- **region 也要声明**：客户端默认 `REG_CN`（`qlib/config.py:300`），不同 region 的
  `limit_threshold` / `trade_unit` / 交易日历不同 ⇒ **跨 region 的数字不可直接比**。

- **只报"年化 30%"而不报上面任何一项 ⇒ 该数字不可用于任何结论。**
- **收益必须与风险同报**：最大回撤、夏普、卡玛、胜率、盈亏比、换手率、
  以及**多头/空头分别贡献**（避免"只是赌对了某个方向"的伪 alpha）。

### 12.2 禁止未来函数 / 幸存者偏差（Look-ahead & Survivorship Bias）

- **特征只能用 t 时刻及之前的数据**；任何用到未来信息的实现一律作废。
- 标的池必须用**历史时点的成分**（point-in-time），不得用今天的成分回溯历史。

**qlib 的 `Ref` 语义（源码核验，`qlib/data/ops.py:789`）**：

```
Ref(feature, N):  N = 0 → 取首个数据;  N > 0 → 取 N 期【之前】的数据;  N < 0 → 【未来】数据
```

- `N > 0` 才是「向后看历史」，**默认方向本身是安全的（严格因果）**。
- ⚠️ **qlib 里没有 `Ref$` 这个算子**。`$` 是**前缀**简写：
  `$close → Feature("close")`、`$$close → PFeature("close")`（`qlib/utils/__init__.py:307-317`）。
- 官方 `Alpha158`/`Alpha360` 的**特征**侧只用 `N ≥ 0`（严格因果，源码核验
  `qlib/contrib/data/loader.py:28-53,128-137`）；只有 **label** 用 `N < 0`
  （`Ref($close,-2)/Ref($close,-1)-1`，`qlib/contrib/data/handler.py:90,152`），
  对应官方文档「T+1 买入、T+2 卖出」的 T+1→T+2 收益（`docs/component/data.rst:488`）——**这是合法的**。

**⇒ 必须逐个确认方向的是这三类（不是官方特征）：**
1. **自研特征表达式**；
2. **`filter_pipe` 的 `rule_expression`** —— 官方文档给的例子
   `Ref($close, -2)/Ref($close, -1) > 1`（`docs/component/data.rst:345`）
   **在决策日应用就是未来函数**；
3. **`P` / `PRef` 点时点算子**（`qlib/data/pit.py:24,63`）。

**🔴 自检手段（look-ahead 探针）——方向不可搞反**：

> 把特征整体**向未来方向**平移一个交易日（`feature_t := feature_{t+1}`）后重跑：
> 对干净的因果流水线，错位后指标**应当显著变差**；
> 若**几乎不变甚至变好** ⇒ 特征里混入了未来信息（或标签与特征的错位恰好被抵消）。

⚠️ **判反的后果是双向致命的**：写成「大幅变差 ⇒ 有未来信息」会把干净特征误报为污染（假警报），
更糟的是把真污染特征判为干净（漏报）——恰好是本条想防的失败。

**⚠️ 语义不确定时，用 oracle 探针把它读出来，不要凭直觉猜**（移植自 yolo §五·「凡是要猜的外部语义，
先用 oracle 探针把它读出来」）。`Ref` 的方向、`deal_price` 的含义、`limit_threshold` 随 region 的变化、
`trade_unit` 随市场的取值，全都是**猜错也不报错**的语义 ⇒ **猜错只会静默产出错误数字**。
**验证工具自身的错误会被当成被验证对象的错误** ⇒ 探针本身也要先自证。

### 12.3 复现性：随机种子必须钉死（qlib 无全局 seed，seed 靠模型构造参数）

**🔴 qlib v0.9.8 没有「框架级 seed」入口**（源码核验）：

- `qlib.init(default_conf="client", **kwargs)`（`qlib/__init__.py:25`）**无 `seed` 参数**；
  `qlib/config.py` 中 `seed` 键 **0 命中**；`qlib/workflow/`、`qlib/model/trainer.py` **0 命中**。
- ⚠️ **把 `seed=42` 传给 `qlib.init()` 会被 `**kwargs` → `C.set()` 静默吞掉**，
  变成一个什么都没做的配置键 —— **这正是本节要消灭的「静默失败」**。
  ⇒ **不要写 `qlib.init(seed=42)`。**
- **唯一的框架级入口是模型构造参数 `seed=`**：`qlib/contrib/model/pytorch_nn.py:67`（`seed=None`），
  且**只在 `fit()` 里生效**（`:123-125` `np.random.seed` + `torch.manual_seed`）；
  同型复制于 `pytorch_lstm.py:108-110`、`pytorch_gats.py:116-118`、`pytorch_gru_ts.py:115-116`、
  `pytorch_sandwich.py:201-203`、`pytorch_add.py:137-138`、`pytorch_adarnn.py:121-122`、
  `pytorch_tcn_ts.py:117-119`、`pytorch_krnn.py:322-323`。
- ⚠️ **`seed=None` 是默认值** ⇒ **「默认不播种」，不是「默认已播种」**。
- ⚠️ **`qlib/contrib/model/gbdt.py` 无 seed 参数**（LightGBM 吃自己的默认值）⇒
  **LightGBM 臂的随机性来源是 LightGBM 自己的 `random_state`**，不在 qlib 这一层。
- 🔴 **反例（钉了种子也不可复现）**：`qlib/contrib/model/pytorch_tcts.py:259`
  `self.seed = random.randint(0, 1000)  # reset random seed`
  ⇒ **TCTS 重训时重置种子** ⇒ 该模型**无法靠 seed 参数复现**。
  另 `qlib/contrib/meta/data_selection/model.py:54,72` 硬编码 `seed=43`。

**⇒ 落地要求：**
1. 涉及随机性的环节**必须显式设种子**（`random.seed` / `np.random.seed` / `torch.manual_seed`
   / 模型构造参数 `seed=`），并在 **manifest 里记录「用了哪个入口」**；
2. **用 LightGBM/Torch 等不同模型时，seed 的挂载点不同 ⇒ 不得声称「已全局固定」**；
3. 产出必须记录：**代码 commit、配置文件、种子、数据版本、依赖版本**；
4. **同一份代码 + 同一份配置 ⇒ 两次结果必须一致**；不一致 ⇒ 先查种子与并发顺序，
   **禁止**归因为「随机波动」；
5. **TCTS 等已知不可复现模型 ⇒ 必须在产物里显式标注「该臂不可复现」**。

### 12.4 数据质量断言先行，禁止"静默空数据"

- qlib 最危险的失败模式是**静默拿到空数据或错对齐的列**：
  特征全 NaN、label 全 0、日期区间为空 ⇒ 脚本**不报错**，但回测结果长得"很正常"。
- **源码核验**：`qlib.init()` 对不存在的 provider 路径**只 warn/error 不抛异常**
  （`qlib/__init__.py:66-72`）；`Config.validate` 只检查 `provider_uri`/`region` 非空
  （`qlib/config.py:72-85`），**完全不检查数据是否存在** ⇒ 「静默空数据」确为真实最危险的失败模式。

**开跑前必须断言：**
- 行数 > 0 且在**预期量级**；
- 关键列**非全 NaN**；
- 日期区间落在**预期范围**；
- **特征列数**必须与 `data_loader.kwargs.config["feature"]` 的表达式条数一致
  （用 `DLWParser` 解析出的 `names` 长度核对，`qlib/data/dataset/loader.py:95-108`），
  并与 `handler.fetch()` 实际返回的列数一致。
  ⚠️ **`infer_processors`/`learn_processors` 不声明列数**——它们是**处理器流水线**
  （`qlib/contrib/data/handler.py:37-45`：`DropnaLabel`/`CSZScoreNorm(label)` vs
  `ProcessInf`/`ZScoreNorm`/`Fillna`），只影响数值处理。
  **写成「列数与 processors 声明一致」是一条不可能失败的恒真空断言** ⇒ 在专门防静默失败的章节里
  塞恒真断言是最坏的一种错。

**🔴 抽样必须剔除「窗口尚未填满的起始区」**（移植自 yolo §三·2）：
`Mean($close,60)` / `Ref($close,60)` 在每只票序列**头部**必为 NaN；
`Alpha158` 的 `DropnaLabel` 丢的是**尾部**而非头部 ⇒ **头部填充与否直接改变 IC 量级**。
抽样报告必须同时打印**序列数**与**窗口填充状态**。

**🔴 必须打印覆盖率 M/N**（移植自 yolo §三·4b）：
「统计了 N 个对象但只匹配上 M 个」必须把 **M/N 打印出来**，`M ≪ N` 时结论一律作废。
例：`instruments='csi500'` 经 `filter_pipe` 后可能只剩 3 只票，回测**照样打印 Sharpe**。
**「静默的部分失败不会自己举手，必须由你主动去数分母。」**

**🔴 守卫必须能被证伪**（移植自 yolo §四·4）：
恒真的断言照样全绿 ⇒ **数量为 0 时必须显示 `SKIP` 而绝不能显示 `PASS`**；
断言失败必须是**显式抛错退出**，**禁止"写空文件兜底"**。
断点续跑保护（`if not dst.exists()`）存在时，**重跑前必须先删上一轮产物**，
否则错误产物永不被覆盖。

**追加写的输出文件必须先清空**（移植自 yolo §五）：
量化回测普遍往 CSV/JSONL **追加**日志，残留旧行直接污染下一轮统计。
（**本工程自己踩过同类**：md5 双侧比对因 locale 排序不同而误报「不一致」，
而两边 md5 值完全相同 —— 见 `manu/memory/env_setup_20261104.md` §5.3。）

### 12.5 数据集路径与版本必须显式指定，禁止依赖隐式默认值

- qlib 默认读 `~/.qlib/qlib_data/cn_data`（源码核验 `qlib/config.py:53`），
  客户端默认 region = `REG_CN`（`qlib/config.py:300`）。
- **本工程一律用绝对路径显式指定**，不依赖 `qlib.init()` 的默认参数。
- ⚠️ **`qlib.init` 没有 `provider_uri` 形参**：真实签名是 `qlib.init(default_conf="client", **kwargs)`
  （`qlib/__init__.py:25`），`provider_uri` 是**配置键**（`MODE_CONF["client"]["provider_uri"]`，
  `qlib/config.py:284-286`），靠 `**kwargs` 生效。
  **优先级链**（`qlib/config.py:165-174`）：`backend_config.kwargs.provider_uri` >
  `backend_config.kwargs.provider_uri_map` > `qlib.init` 的 `provider_uri`。
  ⇒ **别去找一个不存在的形参**；且 `provider_uri` 与 `region` 都是**必填**
  （`qlib/config.py:75-79`）。
- 不同数据集（cn_data / 自建）**严禁混用**；在产出文件里**记录实际使用的 provider_uri 与 region**。
- 数据集**版本化**：`/mnt/data/siping/datasets/qlib/<name>_<date>/`，
  目录内放 `VERSION.txt`（来源、构建脚本、构建日期、文件数、md5）。

### 12.6 指标统计：必须带样本量与置信区间

- 回测指标是**单条时间序列上的统计量**，样本量天然有限。
- **比例/胜率/命中率类指标必须带样本量 n 与置信区间**；小样本会系统性高估。
- **必须给出分子分母的绝对数**（不只是百分比）；**分母不足两个数量级时不允许下分层结论**。
- 两个策略对比**优先用配对检验**（同一时间轴上的逐期收益差），
  **「两条置信区间重叠」不是显著性判据**。
- ⚠️ **量化特有的统计陷阱**：重叠持有期的逐期收益序列**自相关** ⇒ 普通配对 t 检验无效，
  需 **HAC / Newey-West** 或 **block bootstrap**。
- **🔴 跨块聚合的量纲自洽检查**（移植自 yolo §三·4）：累加「和 ↔ 元素数」「均值 ↔ 份数」，
  禁止混用；落盘后强制自洽检查。**同一张表内数字互相矛盾，是聚合 bug 唯一的可靠破绽，必须逐表核对。**
  （yolo 曾把结果除小约 6000 倍，打印出 `1.7e-06` 的假象。）

### 12.7 训练/调参：禁止越级对比，必须同源受控 A/B（量化版）

- **所有调参实验必须固定数据区间与评估区间**，且评估区间**不得参与选参**（否则是信息泄漏）。
- **看验证集选超参、在测试集报成绩**是标准做法；
  **反复用测试集选超参 ⇒ 测试集已污染**，该数字作废，必须换未触碰的区间重测。
- **🔴 qlib 最易踩的泄漏点：`fit_start_time` / `fit_end_time`**
  （`qlib/contrib/data/handler.py:99-113`）—— `Alpha158`/`Alpha360` 有**两套时间**：
  `start_time`/`end_time`（数据区间）与 `fit_start_time`/`fit_end_time`（**归一化/拟合区间**）。
  `CSZScoreNorm`/`ZScoreNorm` 在 **fit 区间**上拟合（`qlib/data/dataset/handler.py:588-607`）。
  ⇒ **`fit_*` 必须严格落在训练段内**，否则归一化统计量把测试期信息漏进训练。

**🔴 A/B 判定前必须先立两个基线**（移植自 yolo §三·6 与 §三·7）：
1. **复现噪声下限**：同一配置**重跑 N 次**（N ≥ 3），量指标散布；
   **效应小于噪声下限 ⇒ 一律不下结论**（不写「略有提升」）。
2. **空对照臂**：把被测组件换成「什么都不做」的版本，**把混淆项钉死**——
   指标差异若在空对照臂上也出现 ⇒ 那不是被测组件的功劳。

### 12.8 产物与可复现清单

- 每次实验产出**必须落盘一个 `manifest`**：
  **本地 checkout 的 commit + `manu/` 是否已纳入版本控制**、配置、**种子及其挂载入口**、
  数据版本、关键依赖版本、耗时、产物文件清单及其 md5。
  ⚠️ **服务器工程目录无 `.git`** ⇒ commit **只能在本地 checkout 取**再带到服务器；
  且本地 `manu/` 若仍是 untracked ⇒ **没有任何 commit 包含 `manu/`**，
  此时 manifest 的 commit 字段必须**显式写明「manu/ 未纳入版本控制」**，不得填一个假值。
- **交付件与实验记录分离**：`manu/experiments/<实验名>/` 存原始产物，
  `manu/evaluation/` 存汇总指标与报告，**不要**把两者混在一个目录。
- **🔴 Git 卫生**：qlib 上游 `.gitignore` **不忽略** `*.bin`/`*.parquet`/`*.pt`/`*.json`，
  也**完全没有 `manu/`** ⇒ **`manu/experiments/`、`manu/evaluation/` 的大产物一律不进 git**
  （须自行补 `.gitignore`）。一次 `git add -A` 就可能把 GB 级回测产物提交进 qlib 仓库。
- **产物目录不得互相覆盖**（移植自 yolo §五）：同一实验名**两次运行不得覆盖**，
  per-stock / per-period 结果文件名必须**能唯一定位来源**；
  **共享输出目录 + 缺少命名空间 = 证据作废**。

### 12.9 交付前的可执行性验证（移植自 yolo §五）

- 交付命令前**必须实测该路径存在**（不是「写上去了」，是**跑一遍确认存在**）。
- **不要把「GUI 配置成功」当作「命令行可复现」**：
  本工程 PyCharm 远程解释器能跑 ≠ 交付给别人的 CLI 命令能跑。
  ⇒ 交付命令**必须在服务器 shell 里实测执行过**。
- **「代码已同步」绝不等于「产物已就位」**（移植自 yolo §三·9）：
  `sync_to_server.sh` 默认只推 `manu/` ⇒ 同步成功**不代表**
  checkpoint / 特征 cache / 数据集已就位。三者要分别确认。
- **「精度等价」与「算力等价」是两件事**（移植自 yolo §四·9）：
  「复现了官方 IC」≠「复现了官方流程」≠「跑得一样快」；
  引用「等价」必须同时给出**覆盖范围**（universe / 区间 / freq）。
- **复现失败时的排查顺序**（移植自 yolo §四·7）：
  种子 → expr/dataset cache 版本 → universe filter → `provider_uri` + 数据版本 →
  `deal_price`/`limit_threshold` → `fit_start_time`/`fit_end_time` → 实际跑的是哪个脚本。
- **「把字典反转一次」是高危写法**（移植自 yolo §五）：
  方向反了仍能「匹配到一部分」⇒ **不会报错，只会静默比对错**。
  量化侧同型：feature index ↔ date ↔ label index 的对齐方向反了，
  指标不会崩，**只会慢慢变差**。⇒ 对齐方向**必须实测断言**，不能靠肉眼。

### 12.10 qlib 组合构造语义坑 ＋ **回测跨进程非确定性**（2026-11-04 实测新增）

#### (1) 原生 `TopkDropoutStrategy` 的换手语义（方向极易搞反）

- qlib 原生策略 **每个交易日**都执行一次「卖旧 + 买新」
  （`qlib/contrib/strategy/signal_strategy.py`：`sell = last ∩ comb 末尾 n_drop`、
  `buy = today[:len(sell)+topk-len(last)]`）
  ⇒ **卖的只数 = `n_drop`，买的只数 = `len(sell)+topk-len(last)`**；
  **只有稳态（持仓数 = topk 且确实卖出 n_drop 只）时买的只数才恰好等于 `n_drop`**
  ⇒ 「买卖各 n_drop 只」只是**稳态近似**，非稳态（持仓数 ≠ topk）会不等。
  ⇒ **换手与 `n_drop` 同向：`n_drop` 越大换手越高**。
  「调大 `n_drop` 降换手」是**错的**（曾犯）。
- 🔴 **`n_drop=0` 不是「买入持有」，是退化臂**：
  `only_tradable=False` 分支里 `get_last_n(li, 0) = list(li)[-0:]` 返回**整个列表**
  ⇒ 每天清仓、次日重建 ⇒ 实测年化单边换手 **217 倍**、含成本年化超额 **-27%**。
  ⇒ 命名与解读必须按实测语义，**不许叫 buy-and-hold**。
- `hold_thresh`（最短持有期）**只挡卖、不挡买** ⇒ 持仓数可能略高于 `topk`。
- ⇒ 降换手的三个可用旋钮：`n_drop` 调小、`hold_thresh` 调大、**调仓周期拉长**
  （后者需自研策略类，见 `manu/experiments/ashare_topk_selection/rebalance_interval_strategy.py`）。

#### (2) 🔴 qlib 回测**跨进程不可复现**（`PYTHONHASHSEED` 依赖）

- 根因：`qlib/backtest/position.py:422` 的 `get_stock_list()` 是
  `list(set(self.position.keys()) - {...})` ⇒ **集合迭代序随 `PYTHONHASHSEED` 逐进程随机**；
  策略遍历持仓的顺序随之变化 ⇒ **下单顺序 → 整手取整(`trade_unit=100`)/现金约束路径不同
  → 持仓漂移 → 指标漂移**。
- 实测：同一 arm、同一 `pred.pkl`、同一 config，**两个独立进程 valid 段年化超额最大差 3.65pp**
  （A5：4.41% vs 8.06%），10/14 个 arm 逐位相同 ⇒ **只在「顺序敏感的 arm」上发散**，
  **不报错、不告警**，极易被误读成「策略不稳定」。
- ⇒ **强制要求**：
  1. 回测一律跑 `manu/experiments/ashare_topk_selection/determinism.py`
     的 `apply_deterministic_position_ordering()`（运行期打补丁，**上游源码零改动**）；
  2. 命令行加 `PYTHONHASHSEED=0`；
  3. **交付任何回测数字前，必须做「同 arm 两个独立进程逐位比对」**，
     差异 > 1e-9 就当数字没跑完。
- 🔴 **推论**：`rules.md §12.3` 的「种子钉死」只管住了**模型**，
  **管不住 qlib 回测框架内部的集合序** ⇒ 种子 ≠ 可复现，必须额外验证。

## 十四、【ETF 轮动线铁律】（2026-11-04 新增，线别：ETF 轮动 / 人工低频）

> 适用：`manu/etf_rotation/`（第三条线）。上位铁律 §〇~§十三 全部继续有效，本节只增补。

1. **人工低频优先**：调仓周期由「**人能执行的频率**」决定，不由「模型能算的频率」决定。
   本线实测基准是 **20 个交易日（月频）**。
2. 🔴 **E = W × S 不得跳过**：不许直接拿 ETF 价格算动量就选股（那就退化成普通动量轮动，
   等于丢掉 qlib 建模的价值）。**个股层必须先跑**（全市场打分 → 矩阵映射 → ETF 决策）。
3. 🔴 **E 是「暴露分」，不是独立 alpha**：实测纯 E（α=1.0）月频超额 **-9.08%**，
   而 α=0.5 与 ETF 自身动量各半 ⇒ **+10.06%** ⇒ E **必须与 ETF 自身动量互补**，
   不许单独用，也不许把 α 权重调满。
4. 🔴 **归一化统计量跨股票池 / 跨窗口复用时必须冻结**：训练期 ZScoreNorm 的
   `mean_train/std_train` 必须**原样带进推理期**（`FrozenZScoreNorm`），
   **不许在推理窗/新股票池上重拟合**（绝对价位特征量纲会漂移 ⇒ 模型被自己的归一化毁掉）。
5. **退化守卫先行**：任何「跑完但输出无信息」的结果必须由断言拦住
   （分数方差 = 0 / 唯一值过少 ⇒ 直接抛错）。**宁可不产出，也绝不产出假结果。**
6. 🔴 **回测评估窗口必须跨场景同窗**：窗口必须由**信号/执行日程确定性推出**
   （首个执行日之后 ~ 末个执行日），**禁止**用「组合实际持有过的日子」反推 ⇒
   否则某场景少跑一期 ⇒ 基准跟着变 ⇒ **场景间超额不可比**。
7. 🔴 **持仓收益区间必须与「收盘调仓」自洽**：信号日 T → 执行日 T+1 **收盘** ⇒
   持仓区间取 **(exec_i, exec_{i+1}]**（左开右闭）。两端都开 ⇒ **每期漏 1 个交易日**
   ⇒ 区间越短、年化口径越漂。
8. 🔴 **「构建组合失败」禁止静默跳过**：`except` 吞掉异常会让回测**无声失真**
   （整期空仓 + 窗口变短）。正确处理：**沿用上一期持仓**（真实交易里「这期没调成仓」
   就是继续持有），并把 `n_failed / n_carried_forward / n_uncovered_days` 写进产物。
   ⇒ 另：列表**下标**与**行位置值**必须分清（`selected_pos[victim] = pos` 型 bug
   会让迟滞分支每次越界崩溃）。
9. 🔴 **调仓频率不是越低越好**：实测 10 日（双周）全负超额、**20 日最优**、40 日（季频）也负 ⇒
   频率**必须用实测网格定**，不许拍脑袋；成本（换手 × 费率）是主因。
10. 🔴 **绝对动量过滤（mom120>0）不是刹车**：急跌中 120 日动量仍为正 ⇒ 过滤不触发 ⇒
    组合无防护（实测 2026H2 组合 -35.96%、基准 -16.82%）。
    ⇒ **不许把它当回撤保护**；真正的急跌防护需另行设计（当前**没有**）。
11. **跨场景对比必须附分段稳定性 + 选择偏差声明**：本线网格是在**同一段 test 区间**扫出来的
    ⇒ 样本内最优；必须同时给出**半年度/两段分解**、**样本量（调仓期数）**、
    **当前回撤位置**；只报一个年化数字 = 违规。
12. **W 的快照偏差与「无 A 股成分」ETF 必须显式披露**：`W` 是当前快照 ⇒ 含成分股历史变更的
    前视偏差；候选池是当前存续 ETF ⇒ 幸存者偏差；**无 A 股成分的 ETF（美股/港股通/实物金）
    其 E 算不出来（coverage=0）** ⇒ 报告必须点名，不能假装它们也有 E。

2. 🔴 **静默漏算 = 假结果**（与 §十四.5 同源）：宁可**抛异常**（节点日与计划件都没价）也不许静默跳过。
3. 🔴 **计划外持仓必须显式登记**：明细行加 `in_plan_actions` 布尔位；
   汇总里加 `n_off_plan_holdings` / `off_plan_holdings`；
   `basis_note` 与**风险披露**各写一条「计划外持仓已计入总资产，若不在目标名单里就是**未被处置的存量持仓**」。
4. 🔴 **「计划件口径」与「账户口径」不可混称**：本工具只重算股数、**不生成卖出指令**
   ⇒ 计划外持仓即使被计入总资产，也**没人会卖它** ⇒ 必须提示人工确认。
5. 🔴 **闸门必须为这类缺陷留防线**：新增探针断言 **P15** —— 构造含计划外持仓的账户快照 ⇒
   断言 `node_total_assets` 与「现金 + Σ(快照**全量**持仓 × 节点日价)」**独立重算一致**，
   且计划外持仓被登记。**探针有牙实测**：把工具改回旧行为 ⇒ P15 FAIL（29854.67 ≠ 34029.67）。
6. **推广**：凡是「用某份文件驱动」的遍历（计划件 actions / 候选池 / 持仓表），都要问一句：
   **这份文件是全集吗？** 不是 ⇒ 必须显式登记差集，不许默认相等。

### §十四.88 表格结构判定必须按「**未转义**竖线」，且要接进闸门（M-S6，2026-11-05）
1. 🔴 **`line.count("|")` 会把「引述表头」误判成断表**：memory 主档里大量单元格**故意**引用别处的表头
   （如「代码\|当前权重\|机械目标\|熊方动作」）⇒ 用 `\|` **转义** ⇒ 渲染成字面竖线，**不是**单元格分隔符。
   实测：上一轮登记的「4 行 6 竖线 ⇒ 表格错位」里 **3 行是假阳性**，真错位**只有 1 行**。
   ⇒ **正确口径**：统计**未转义**竖线数（逐字符扫描：遇 `\` 跳过下一字符 ⇒ `\|` 不计、`\\|` 计）。
2. 🔴 **代码段里的 `|` 也必须转义**：`` `ls || true` `` 里的两个竖线未转义 ⇒ 该行被切成 **5** 格
   （3 列表 ⇒ 渲染错位）。修法：写成 `` `ls \|\| true` ``（**渲染文字不变**，只改 markdown 编码）。
3. 🔴 **判据不许用「第一行」当标尺**：实测**坏行恰好是首行**时，用首行列数会把后续 3 行误报成缺陷、
   反而**漏掉坏行** ⇒ 改用**块内众数列数**（并列取首行）⇒ 精确锁定唯一少数派坏行。
4. 🔴 **自己写的内容也要过结构检查**：本轮新增的 M-S6 行里就写了裸 `` `|` `` ⇒ 当场由扫描抓出并修掉。
   ⇒ 「写完表格 ⇒ 跑一遍结构检查」必须是**收尾动作**，不是可选项。
5. 🔴 **结构检查要接进闸门**：新增 `manu/tools/check_memory_tables.py`（**只读**）并作为 `run_gates.sh`
   **第 17 阶段** ⇒ 表格错位**在闸门里就会 FAIL**，而不是等人/LLM 读到错位的真值。
6. **推广**：任何「按分隔符切分」的解析（表格、CSV、命令行参数）都要问一句：
   **这个分隔符有没有转义/引号语义？** 没有 ⇒ 计数型校验会把**引述**当**结构**。

### §十四.89 决策分歧必须给「**组合后果**」矩阵，并配独立重算 + 漂移闸门（M-S6，2026-11-05）
1. 🔴 **逐项对照 ≠ 组合后果**：只给「每项各自选 A 还是 B」的表，用户拍板时看不到「三项一起选」的
   账户后果（期末现金 / 权益 / 破单席 / 可执行性）⇒ 必须补 **2^n 全组合情景矩阵**
   （本次 n=3 ⇒ **8 情景**），每个情景给：最终股数、期末现金、权益金额与 %、现金 %、总资产、
   与账户总资产的差额（拆成**费用** + **价格基差**两项）、破单席项、整手不可建仓项、负现金硬拦。
2. 🔴 **差额必须拆项，不许只报一个净差**：情景总资产 = 账户总资产 − **价格基差** − **本情景费用**
   ⇒ 费用是唯一损耗、价格基差是口径差（账户快照价 vs 规则层价格）。本次：基差 **72.30 元**、
   费用区间 **5.438875 ~ 17.420390 元**；8 情景残差须为 **0**。
3. 🔴 **矩阵里的数必须能被独立重算**：闸门探针**不许复用生成器函数**，要自己从
   `final_rebalance_plan.json` 的 `actions` 手推现金 / 权益 / 总资产（卖出与买入**都**按单边费率计费）。
4. 🔴 **矩阵产物必须配漂移闸门**：与已交付的 `decision_scenarios_*.json/md` **逐字节一致**才算 PASS
   （计划变了而矩阵没变 ⇒ FAIL）；且要有**真负例**（篡改副本 ⇒ 闸门必须 FAIL）证明它有牙。
5. 🔴 **权重分母要写明**：情景表的「现金% / 权益%」分母若用账户总资产，则两列之和 **< 100%**
   （缺口 = 费用 + 基差）；JSON 里要**同时**给出情景内占比（两列之和恒 100%）供交叉核对。
6. **仍然不替用户做决定**：矩阵只摆事实与后果（`可执行` / `破单席` 是**事实标记**，不是结论），
   全文不许出现「建议采用 X」式措辞（同 §十四.87）。
7. **推广**：任何「N 个独立开关」的决策面（情景 / 组合 / 配置）⇒ 都要给**全组合后果**，
   并把「组合数爆炸」的成本显式记下来（n=3 ⇒ 8；n=5 ⇒ 32 ⇒ 需要抽样或分层时必须写明口径）。

### §十四.90 用户拍板后，节点日清单必须**可算**（M-S7，2026-11-05）
1. 🔴 **「拍板前的表」≠「拍板后的清单」**：逐项 A/B 对照表只回答「有哪几个选择」，
   用户拍完板后必须能拿到**该选项在节点日价格下的股数 / 金额 / 费用 / 期末现金 / 权益** ⇒
   必须有一条「拍板 ⇒ 重算」的**工具链**，而不是让用户自己心算。
2. 🔴 **覆盖语义只认显式字段，不许猜**：`lots` 非空 ⇒ 买 N 手（固定 **N×100 股**，与价格无关）；
   `target_pct == 0` ⇒ **不建仓**；`target_pct` 有值 ⇒ 权重 = 该百分比；
   **选项 A = 规则层（不覆盖）**。不许从 LLM 原文里「猜比例」，也不许把「LLM 提到了某标的」
   当成「要买它」⇒ 解析不出来就**报错**，不许默认。
3. 🔴 **默认路径必须零回归**：新增能力一律走**可选参数**（如 `overrides=None`），
   老入口产物要能**逐字节比对**（基线备份 → 剔除时间戳后 JSON **逐字段一致** + MD 差异 **0 行**）；
   🔴 若已有**源码级变异测试**按精确文本绑定某几行，**签名与那几行字面量不许动**。
4. 🔴 **算法单一事实源**：编排器（如 8 情景批量器）**不许自己实现**股数 / 费用 / 现金流算法
   ⇒ 全部委托底层重算器，避免两套算法各写各的、日后漂移。
5. 🔴 **「不可建仓」与「破单席」必须分开说**：前者 = **整手买不起**（结构性、无解），
   后者 = **买得起但超过单席上限**（待裁决项）；两者混成一句「买不满」= 误读。
6. 🔴 **必须披露「买不满」的规模**：落地**持仓只数**、**权益占比区间**、**现金区间**
   都要写进产物 `notes`，并写明这是**结构性问题**（例如货基一手 ≈ 10,000 元 > 单席 ≈ 5,971 元）
   而**不是选股问题** ⇒ 否则用户会误以为「再挑几只就能凑齐 5 只」。
7. **推广**：任何「用户拍板 → 具体下单」的链路，都要有**三层**：拍板前对照表 +
   全组合情景矩阵 + **拍板后单情景可执行清单**；缺第三层 ⇒ 拍完板仍然无法下单。

### §十四.91 解析器与探针必须**措辞无关**（M-Q 轮，2026-11-05 10:0x~10:4x）
1. 🔴 **「部分卖出」≠「清仓」**：动作规则**必须分层、且顺序敏感**（先匹配先生效）——
   ① 清仓类（全部卖出 / 卖出全部 / 清仓 / 清掉 / 清零）⇒ 卖 + 目标 0%；
   ② **带数量**的「卖出 N 份/股」⇒ **减**（部分卖出，目标权重**另找**，不许当 0%）；
   ③ 裸「卖出」⇒ 卖 + 0%。实测事故：「减至约 5,100 份（卖出约 2,600 份），权重降至约 14.9%」
   被旧规则读成「清仓 ⇒ 0%」⇒ 交付件的最终裁决方向**完全错位**。
2. 🔴 **否定式必须被识别**：「**不清零**」「**不是清零**」「避免清仓」里的动作词**不算数**
   ⇒ 动作词匹配要带**否定式保护**（回看前 4 字窗口找否定词）。
3. 🔴 **组合层数字不许归给单只标的**：「**权益敞口 / 总权益 / 敞口 / 权益**」是**组合级**
   ⇒ 进独立字段（如 `post_trade.equity_pct`）；「**目标权重 / 权重 / 仓位 / 目标 / 风险预算**」
   才是**单只标的级**。实测事故：「…与 563020 均不买入，**权益敞口由 48.02% 降至约 15%**」
   ⇒ 15% 被记到 563020（真实裁决 0%）头上 ⇒ 交付件出现**幽灵数字**。
   🔴 组合层数字常出现在**没有代码**的句子里 ⇒ 组合层抽取**不许**要求句内有代码。
4. 🔴 **条件句 / 触发器句里的数字不是裁决**：句首「若 / 如果 / 一旦 / 除非 / 只有当」，
   或**首个子句**含条件词（若 / 如果 / 一旦 / 除非 / 条件 / 触发）⇒ 整句跳过；
   但「**条件买入 / 条件建仓**」是**动作**不是条件 ⇒ 判条件前先把这三个词抹掉。
5. 🔴 **6 位代码首位不得为 0**：「最终分差仅 0.006126 / 0.019181」里的 "006126" **不是代码**
   ⇒ 抽成代码会让「未能结构化提取」列表出现**根本不存在的标的**。
6. 🔴 **断言不许抄现状**（本轮最重要的一条）：探针断言的期望值**不许**从当轮产物反推
   ⇒ 必须**措辞无关 + 内容无关可回放**，且必须配**真负例（突变测试）**：改了实现断言就得 FAIL。
   🔴 特别地，**数量下限类断言**（「买入类目标必须 ≥1」）在**合法空集**（本轮裁决就是一个
   买单都没有）时必须判「**不适用**」而不是 FAIL —— 否则就是把**旧决策的形状**当成了金标。
7. 🔴 **最终裁决不许裁**：交付件里「最终交易决定 / 最终裁决」章节**整段保留**
   ⇒ 裁剪只允许发生在**非裁决**区；A19④ 用「回退旧实现 ⇒ 表格块数必须严格少」来证明
   「整块保留」起作用 ⇒ **选错了对象**（两个版本表格块数本来就一样），
   应改为「裁决章节**逐字**出现 / 回退旧实现必须被截断」。
8. 🔴 **同值不许覆盖来源标注**：抽取一律**先到先得**（第一次命中即定性）；
   值相同就**保持第一次的来源与证据句**，不许被后面那条来源标签不同的规则改写。
9. 🔴 **抽不出就是抽不出**：`unparsed_codes` / `None` 是**合法交付物**
   （原文只提了名称、没给数字）⇒ 不许为了「列表好看 / 必须为空」而编数字。

### §十四.92 闸门探针不许写死「当前快照」，展示件完整性必须「事实源 × 展示件」交叉校验（M-Q 轮，2026-11-05 11:0x~11:3x）
1. 🔴 **探针里的「期望值常量」会过期**：把上一轮的答案抄成常量
   （实测事故：`probe_decision_scenarios.py` 把「选项 B 的落地股数」写死成
   `{"511880": 100, "512800": 4000, "563020": 0}`）⇒ 交付件一更新，探针就在拿**过期快照**当金标
   ⇒ 要么误红、要么把真错放过去（当时 P6 就是这么红的：权益差 +1,144.00、现金差 −10,100.36）。
   ⇒ 期望值必须**从上游输入推导**：规则层取 `plan.actions[].target_shares`；
   LLM 层取 `plan.llm_final_decision.targets[]`（方向 / 保留手数 / 目标权重）再按「整手买不起 ⇒ 0 股」兜底。
   🔴 推导值必须**独立**于被校验的产物（拿产物自己的答案当期望值 = 自证）。
2. 🔴 **展示件的完整性不许用展示件自己的结构切分**：交付 md 是渲染器 `_render_md()` 机械渲染的，
   而**多头 / 空头正文里嵌着 LLM 报告自带的 `##` / `###` 标题**
   （多头体内有 `## 一、`…`## 三、` 与 `### 1.`…`### 4.`；空头体内有 `## 一、`…`## 五、`）
   ⇒ 任何「按标题层级切小节」的写法**必然误切**（旧实现切在 159 行，撞上多头体内的 `### 1.`
   ⇒ 误判「多头小节内没有表块」⇒ P6/P7/D1/D2 四条一起红）。
   ⇒ 正确口径：**决策 json（事实源）的每张表块，必须在交付 md（展示件）里逐字出现**；

   且会把「表结构是否合法」误判成「两家必须同 schema」。
   ⇒ 只做**逐表块**校验（块内行内 `|` 数一致 + 行数下限）。
4. 🔴 **变异负例必须覆盖每一侧**：只测「空头侧表块消失」（D1）⇒ **多头侧判据没有任何负例**

5. 🔴 **定位器要按「表头 + 行数」定位，不许按数据行定位**：否则一行被腰斩会让整块「定位失败」
   ⇒ 把「内容坏了」误报成「表不见了」⇒ 真正该抓残行的「块内 `|` 数一致性」就抓不到。
7. 🔴 **重生成「指纹 / 清单 / 索引」类文件时，必须断言「条目集合不变」**：

   - **单只增量写**（`update_qlib_daily_bar()`）仍**默认 dry-run**（只报告不写盘）；真写前**必须**做**复权守卫**：沿用上一交易日的 factor，用 akshare 的**日涨跌幅**与 qlib 复权序列的**日收益**比对，差异超阈值（`FACTOR_DIVERGENCE_THRESHOLD = 0.02`）⇒ **该股剔除、不写脏数据**（记进 `diverged`）；理由：qlib 二进制一旦写进脏复权数据，会**污染其后所有回测 / 打分**，且极难归因；
   - 🔴 **S 层重跑在模式 B 默认开启**（`--refresh-scores`，≈ **27 分钟**）：`qlib_scores.py` 的落盘是**整体覆盖** `stock_scores.csv`、**不是增量** ⇒ 真刷新必须「临时目录 → 先备份 canonical → 合并回 canonical」，且须**用户当轮授权**（铁律一）；
   - 🔴 **模式 A 路径永远不碰 S 层**（无论开关怎么给）⇒ 日常巡检不会覆盖历史打分日；
   - 🔴 **「无新增交易日 ⇒ 不换库」闸门（2026-11-05 补）**：上游 `chenditc/latest` 的日历**推进会滞后**
     （实测 2026-11-05 拉到的快照仍停在 **2026-11-03**）⇒ 此时换库**收益为零**（覆盖不到信号日），
     却要动**现役生产数据集**（旧库进备份、新快照上位）⇒ **无收益的风险动作 ⇒ 不做**，只写 notes 披露；
     ⚠️ 这**不是** fail-closed：**日历前缀不一致 / 日历不自洽仍然硬拦**（抛异常），这里只是「没必要就不换」。

   - 🔴 **「打分日 ≠ 信号日」的语义边界**（2026-11-05 模式 B 实跑坐实）：
     上游日历滞后时，阶段 2 的 S 层**只能打到数据集末日**（实测 **打分日 2026-11-03 ≠ 信号日 2026-11-05**）
     ⇒ ① 报告 notes **必须披露**这个错配（数字要指到产物：数据集末日 / 栅格末日）；
     ② **节点日重算（`reprice_node_day.py`）只重算股数与金额，不产生新信号**（名单与目标权重仍来自计划件）
     ⇒ 执行卡**不是**「按新信号」的清单 ⇒ 报告风险披露里必须写这句；
     ③ 要把打分推到信号日，**顺序不能反**：**先**让阶段 1 把数据集刷新到信号日之后，**再**重跑阶段 2
     ⇒ 单靠「重跑阶段 2」**推不动**打分日（没有新数据可打）。

6. 🔴 **授权码 / 密钥只进 0600 文件，不进版本库、不进日志、不进邮件正文**
   - 126 **客户端授权码**只写进服务器 `/mnt/data/siping/secrets/smtp.env`，权限必须 **0600**（过宽 ⇒ 代码**直接忽略该文件并报错**，因为明文躺在 0644 文件里 = 没有授权码这道门）；

7. 🔴 **「有必要的时候更新 memory」：结论变 / 工程结构变 / 新增决策口径 ⇒ 当轮必须回写 `manu/memory/memory.md`**
   - 每日流水线每天都会产生**新事实**（当天结论、当天产物、当天邮件是否发出）⇒ **不写 memory 的每日链 = 没有事实源的每日链**；
   - 触发场景（与 `§十四.93` 第 1 条的清单同源，此处点名每日链）：① **结论变了**（模式 A 的趋势判定、模式 B 的执行卡数字）；② **工程结构变了**（新增 / 删除目录、入口命令、cron 调度口径、依赖）；③ **新增决策口径**（新常量、新阈值、新账户口径）；
   - ⇒ **当轮**回写 `manu/memory/memory.md`（事实与数字）＋ 必要时 `manu/memory/rules.md`（铁律）
     ＋ **`manu/memory/memory_compact.md`（速览卡）＋ `manu/memory/.slim_memory.md`（精简档）**,
