# 逐日事实记录（ETF 轮动线）

## 这是什么

**铁律 §十四.122**（2026-11-19 用户亲定）的落地载体：

> 「你写memory的时候不注意记录核心信息，比如当天etf的权重等，方便我几个月以后复盘，
> 这些都是你在akshare开源数据接口拿不到的信息……把这一条写到rule里面，作为铁律。」
> 「不一定写memory,也可以单独开个record什么的，记录。」

⇒ akshare / qlib 只有**行情与基本面**；「我当天为什么买 / 没买、买多少、为什么被否」
**事后压根拿不到** ⇒ 每轮跑完**当轮**必须落成可复盘的事实记录。

## 两个载体，分工明确

| 载体 | 装什么 | 不装什么 |
| --- | --- | --- |
| **memory 四层**（`memory.md` / `.slim_memory.md` / `memory_compact.md` / `rules.md`） | 口径、铁律、方法论、结论 | 不塞逐日明细（避免 memory 膨胀） |
| **本目录**（records） | **逐日事实明细**：每只 ETF 当天的目标权重 / 金额 / 股数、是否成交、否决理由、顺延补位者、V2 参数、账户口径、是否走兜底、失败环节 | 不写方法论、不放大数据文件 |

两者**互相引用**：本目录写明来源快照 / 报告文件名；memory 写明指向对应的 record 文件与台账行。

## 目录内容

- `etf_rotation_daily_ledger.csv` —— **逐日台账（一行 = 一只 ETF 一天）**，
  **append-only**（只增不改）。列见文件首行。
  口径变了**不许改写旧行** ⇒ 追加新行，旧行标「作废」，保留完整演化轨迹。
- `<YYYYMMDD>.md` —— 当日**人读记录**，六个段落：
  ① 一、当日标的（目标 vs 实际分列）② 二、现金流与落地 ③ 三、门槛与纪律
  ④ **四、持仓明细与净值口径** ⑤ **五、执行口径** ⑥ 六、来源。
  （🔴 ②里带一张**「执行卡口径的现金流」对照子表**；③里带**费率口径分歧**与 **`w_holdings` 陈旧度**两行
  ⇒ 细节见下表「另有三类『双口径／陈旧度』披露」）

🔴 **四、五两段是「akshare 拿不到」的专门留痕**（2026-11-20 补齐）：

| 段落 | 装什么 | 来源产物 | 为什么必须留 |
| --- | --- | --- | --- |
| 四、持仓明细与净值口径 | **成本额 / 浮盈 / 浮盈%**、快照总资产、**收盘口径净值（nav_state.nav）**、两者差额、峰值与回撤、已清仓标的、**账户三价差披露原文** | `account_context.json` + `nav_state.json` | 成本与浮盈是**我自己的账户事实**，行情接口永远查不到；`nav` 与快照总资产**本来就不等**（估值口径差），差额必须显式写出来，否则几个月后复盘会对不上账 |
| 五、执行口径 | 执行卡 `execution_basis` / `execution_date` / `price_basis_note` / `live_trade` / `order_enabled` ＋ 计划件 `execution_discipline` ＋ **执行卡自己 warnings 里的盘口声明** ＋ 执行卡 `orders`（股数/价格/市值/目标金额） | `execution_card_*.json` + `final_rebalance_plan.json` | 🔴 **盘口口径分裂**：本轮实测 执行卡＝**开盘**（每日链权威）／计划件＝**收盘**（研究链）⇒ 差一个盘口；🔴 但**标签是从原文派生的**（降级卡会写「未声明」），且**同一张卡自己的 warnings 也写着「收盘成交」** ⇒ 复盘时两处原文都要看 |

🔴 四段里带一条**自校验**：`nav_state.equity_drawdown_vs_peak` 与组合口径 `drawdown`
对不上时（当前为 **−0.7684 vs 0**，字段口径有伪）⇒ 记录会**显式印出「本记录不采信」**，
复盘回撤一律以 `drawdown` 为准（缺陷明细见 `manu/memory/memory.md` **⑨ 段 · 新缺陷 B**）。

🔴 五段里带一条**口径对照**：`execution_basis` 与 `execution_discipline.rule` 的盘口
（开盘/收盘）**由原文派生**，不一致时记录会**显式写「差一个盘口」**；
同时抄录**执行卡自己 `warnings` 里的盘口声明**（同一张卡里可能同时出现两种盘口）⇒
复盘时**两处原文都要看**（缺陷明细见 `manu/memory/memory.md` **⑧ 段**）。

🔴 **另有三类「双口径／陈旧度」披露**（2026-11-20 第四轮补齐）
—— 🔴 **只进当日记录 md，不进台账 30 列**（台账列集恒定，见下方「列口径对照」）：

| 披露 | 落在记录哪 | 来源产物 | 为什么必须留 |
| --- | --- | --- | --- |
| **① 成分股快照 W 的陈旧度** | 头部一行 ＋ §三 一行 | `snapshot_manifest.json` 的 `stages[]` 里 `name == "w_holdings"` 那项（`status` / `max_fetch_date` / `stale_days` / `n_codes`） | 🔴 `w_holdings` 的状态是 **`stale`**，而「失败环节」只认 `failed`/`error`/`degraded` ⇒ **旧口径永远显示不出它** ⇒ 不留痕就误以为「成分股是当天的」；实测 **11-19 滞后 15 天 / 11-18 滞后 14 天**（🟡 只滞后、**不构成前视**） |
| **② 费率口径分歧** | §三 五行 | 执行卡 `constraints.commission_rate` / `slippage_rate`（**小数** ⇒ ×10000 换 bp）＋ 计划件 `meta.commission_bp` / `meta.slippage_bp` | 🔴 实测两处**确实不一致**（计划件 **1.5 bp / 5 bp** vs 执行卡 constraints **3 bp / 1 bp**）⇒ 只写一套 ⇒ 复盘算不出真实摩擦成本 |
| **③ 现金流双口径** | §二 对照表 ＋ `cash_end` 差额行 | 计划件 `cash_flow` ＋ 执行卡 `cash_flow` | 🔴 同一天、同一张计划，**执行卡与计划件各有一套 `cash_flow`** ⇒ 期末现金可能不等（实测 **11-19 ＋0.00**、**11-18 −7.22 元**）⇒ 只留一套 ⇒ 对不上账 |

⇒ 🔴 这三类都有**常驻守卫**：`manu/etf_rotation/tests/test_daily_record_disclosure_guard.py`
（与 `manu/tests/` **逐字一致**）⇒ 删掉任一披露 ⇒ 守卫**转红**（含 **3 段变异反证**）。
⇒ 🔴 表格结构由 `check_memory_tables.py` 覆盖（默认文件集已含 `records/*.md`，2026-11-20 起）。

## 怎么写

```bash
# 从一次不可变快照生成当日记录 + 追加台账
python3 manu/tools/append_daily_record.py \
    --snapshot-dir <RESULTS_ROOT>/snapshots/<run_id> \
    --records-dir manu/memory/records
```

工具**只读快照产物**（执行卡 / 计划 JSON / manifest / 冻结参数 / 账户事实源），
读不到就写 `缺` —— **不许猜、不许事后补算**（铁律「数字不许编」）。

## 落点纪律

本目录是**文档事实源**，不是产物堆放地：

- 具体运行产物（快照 / 报告 / 执行卡 / `pkl` / 行情 `csv`）仍只许落 `<RESULTS_ROOT>` / `<DATASET_ROOT>`（铁律十六）；
- 本目录**只记结论与事实**（数字 + 日期 + 来源 + 判据），**不许**把大文件拷进来；
- 台账 `.csv` 已被 `.gitignore` 的全局 `*.csv` 误伤 ⇒ 已显式白名单放行（`.gitignore` + `.gitattributes` 的 `-text`）。

## 🔴 列口径对照（复盘时防「同名不同义」）

台账与当日记录里的列**全部来自快照产物**（`final_rebalance_plan.json` / `execution_card_*.json` /
`snapshot_manifest.json`），**不许事后补算**。🔴 下面几列**极易混淆**，复盘时务必按此对照：

| 台账列 | 取自产物字段 | 含义 | 易混点 |
| --- | --- | --- | --- |
| `目标金额` | `actions[].target_amount` | **目标持仓市值**（目标股数 × 目标价） | 🔴 **不是** `est_amount`（那是**本笔拟成交额**，维持行 delta=0 ⇒ **0**）|
| `计划金额` | `actions[].est_amount` | **本笔拟成交金额**（买/卖） | 观察态恒为 0（不产生成交）|
| `当前权重` / `目标权重` | `current_weight` / `target_weight`（`target_weight_effective` 同值） | 占总资产比例 | 🔴 **只在买入行**才等于 `目标金额 ÷ 总资产`；**维持行不成立**：权重＝**券商快照市值** ÷ 总资产，而 `目标金额`＝目标股数 × **节点日收盘价** ⇒ 两者差额就是记录 §四 的「收盘口径 − 快照口径」（11-19 为 **+30.80 元**、11-18 为 **+369.60 元**）|
| `目标股数` | `actions[].target_shares` | 目标持仓股数 | 维持行 **＝ 当前股数**（不整手重算）|
| `当前股数` | `actions[].current_shares` | 账户事实源持仓股数 | 来自用户截图口径，**不是**行情推算 |
| `权益上限(规则硬)` / `权益上限(本轮生效)` | `equity_cap` 硬值 / 本轮 TA 生效值 | 权益敞口上限 | 两者**不同**（硬 0.8 vs 生效 0.15）⇒ 复盘超配要按**生效值**算 |
| `是否成交` | — | 观察态恒为「否（观察态不下单）」 | 🔴 观察态**永不**成交，别当成交记录读 |
| `失败环节` | `manifest.stages[*].status`（`failed`/`error`/`degraded`）＋ `manifest.skipped` | 哪一轮失败/被跳过 | 🔴 **工具不按这一列作废**：作废只由「同键行内容签名变化」驱动 ⇒ **降级 run 的行可能仍是「有效」** ⇒ 复盘时**必须自己看这一列**再决定采不采信（manifest 顶层**没有** `pipeline`/`failed_stages` 字段）|
| `记录状态` | — | `有效` / `作废` | **同一 (日期,代码) 可有多行** ⇒ 演化轨迹，**不是重复** |

⇒ **同 (日期,代码) 多行是设计**：口径变了或重跑过 ⇒ 追加新行 ＋ 旧行标「作废」（**不删**）。

🔴 **台账里没有的、只在当日记录 md 里的口径**（复盘时**必须**回看记录 md，**光看台账会漏**）：
`w_holdings` 陈旧度（①）｜执行卡 `constraints` 费率与**费率口径分歧**（②）｜**执行卡口径的现金流**与 `cash_end` 差额（③）｜
持仓成本额 / 浮盈 / 收盘口径净值与差额（§四）｜执行卡 `orders` 表与盘口证据（§五）。
⇒ 理由：台账是**一行 = 一只 ETF 一天**的**窄表**（30 列恒定），装不下这些**跨行 / 跨口径**的事实。
