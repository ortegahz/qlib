## 3. 三个实测坑（每次都会撞）

### 3.1 `ssh` 必须加 `-F /dev/null`

```
Bad owner or permissions on /etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf
```
该文件是 `lrwxrwxrwx 1 nobody nogroup` → `/usr/lib/systemd/ssh_config.d/...`，
sshd 拒绝加载 ⇒ **所有 ssh/scp/rsync 必须 `-F /dev/null`** 绕过系统 ssh_config。

## 5. 同步机制（自建，仿 yolo 的 `push_and_start.sh`）

### 5.1 为什么需要自建
- **PyCharm 的 SFTP 自动上传**（`.idea/deployment.xml`，`autoUpload=Always`，映射 `local=$PROJECT_DIR$` → `deploy=/tmp/pycharm_project_658d3fc4`）
  **只覆盖「在 PyCharm GUI 里改的文件」**；Agent 在**命令行**改的文件 PyCharm 不感知 ⇒ 仍需兜底通道。
- **SSHFS 镜像只读** ⇒ 不能靠写挂载点推送。

### 5.2 成品
`manu/tools/sync_to_server.sh` —— rsync over ssh + **md5 双侧比对**（铁律三要求的唯一判据）：
```bash
bash manu/tools/sync_to_server.sh              # 同步 manu/ 全目录
bash manu/tools/sync_to_server.sh manu/memory  # 只同步子路径
bash manu/tools/sync_to_server.sh --dry-run    # 预演
bash manu/tools/sync_to_server.sh --check      # 只比对不同步
```

### 5.3 实测踩坑：md5 比对的 locale 假阳性
首次运行报「不一致」，但 diff 显示**两边 md5 值完全相同、仅行序不同**。
根因：两侧 `sort -z` 受各自 locale 影响，`manu/memory/memory.md` 与 `memory_compact.md` 的序不同。
⇒ 修法：两侧统一 `LC_ALL=C sort -z`。修复后复测：**5 个文件两侧 md5 完全一致** ✅。

> 📌 这条本身是铁律三的注脚：**「md5 双侧比对」不是把两串文本 `diff` 一下就行，
> 必须先保证两侧的**样本集与排序口径一致**，否则会得到「值相同但报不一致」的假阳性，
> 进而让人误以为同步失败而去乱改——这比不比对更糟。**
